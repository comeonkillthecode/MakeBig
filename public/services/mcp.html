In plain terms

What an MCP server does

MCP is an open standard for connecting AI assistants to outside tools and data. Anthropic introduced it, and Claude, ChatGPT, Cursor, VS Code and other AI apps now support it.

An MCP server is a small service that offers the assistant a short list of tools, such as "find an order", "check stock for a SKU" or "create a discount code". The assistant decides when to call them. Your server decides what it's allowed to do.

Build it once, and it works in every assistant that supports MCP. Your team gets the same Shopify or CRM access in Claude, ChatGPT or their code editor.

example-store-mcp: toolsaccess
find_order          read   order by number or email
list_low_stock      read   SKUs under threshold, by location
get_product         read   variants, price, inventory
sales_summary       read   revenue by day, channel, product
create_discount     write  needs approval, max 20% off
tag_customer        write  limited to the "vip" and "wholesale" tags
refund_order        not exposed, by design

What we build

Shopify is what we know best, but the same approach works for any system with an API or a database.

Shopify MCP servers

Give your team's assistant access to orders, products, inventory, customers, discounts and metafields through the Shopify Admin API. Typical uses: answering "where is my order" faster, inventory checks across locations, sales questions in plain English, bulk product edits with a review step.

Admin GraphQL API · Storefront API · custom app or private install

MCP for your own systems

Your backend, internal APIs or database, exposed as a small set of safe, well-described tools. Read-only by default. Write actions are added one at a time, with limits.

PostgreSQL · MongoDB · REST / GraphQL services · Java / Node.js backends

MCP for SaaS products

If you run a software product, an MCP server lets your customers use it from their own AI assistant. We build it on top of your public API, with OAuth so each user signs in as themselves.

Remote MCP (Streamable HTTP) · OAuth 2.1 · per-user scopes

Safety

What every server ships with

  • Least privilege. Only the API scopes the tools need, and read-only unless you ask for more.
  • Guarded write actions. Limits on amounts and counts, and a confirmation step for anything that's hard to undo.
  • Sign-in. OAuth or API keys per user or team, never one shared admin token.
  • Audit log of every tool call: who, what, when and the result.
  • Clear tool descriptions, so the assistant picks the right tool and doesn't guess.
  • Hosting in your account: Vercel, AWS, GCP, Azure or Cloudflare, with the code in your repository.

Questions

Doesn't Shopify already have MCP?

Shopify provides some MCP servers of its own, for example for storefront shopping and developer documentation. We use those where they fit. Custom servers cover what they don't, which is usually your admin data (orders, inventory, customers) and the workflows specific to your business.

How is this different from a chatbot?

A chatbot is something we build and put on your website for your customers. An MCP server gives an assistant you already use, such as Claude or ChatGPT, the ability to work with your systems. A sensible path is to start with MCP for your own team, then build a customer-facing chatbot once you trust the answers.

Can the AI do something destructive?

Only if a tool allows it, and we don't build tools that do. Refunds, deletions and bulk price changes are either left out or wrapped in limits plus a human confirmation. The server enforces this regardless of what the assistant asks for.

Local or remote server?

Local (stdio) servers are quick for one developer's machine. For a team or customers we build remote servers over HTTP with proper sign-in, so nobody has to install anything or hold credentials on their laptop.

Want your assistant to work with your store or systems?

Tell us which system and the first three things you'd like to ask it. That's usually enough to scope a first version.
